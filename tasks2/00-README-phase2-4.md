# 句子填空之后:第二~四阶段 · 接力实施总览

**给用户看的**(不用发给 AI)。沿用第一阶段的做法:每个步骤一个独立 `.md`,**自带全部规则**,可以交给不同的 AI。设计依据是你的 `word-cloze-design.md` 第 7 节,具体细节在其基础上补全了。

## 一、三个阶段做什么

| 阶段 | 一句话 | 主要改动 | 数据库 | 需要你额外做的事 |
|---|---|---|---|---|
| **P4 多例句轮换** | 每个词再生成 2 条例句,填空时轮换;**还能把"例句里是变位/复数、挖不出空"的 22% 的词救回来** | 新增 `word_example_manager.py`、`tools/gen_examples.py`;改 `word_routes.py`、`words.js` | 新增 2 张表 | **在你本机跑批量生成脚本**(消耗 LLM 额度,可断点续跑) |
| **P2 聊天联动** | 教练聊天时自然带入你最弱的几个词;你在对话里用到了,该词熟练度 +1(只对 box≤2、封顶 3、**聊天绝不让词毕业**) | 新增 `pt_text.py`、`chat_words.py`;改 `tutor_prompt.py`、`routes.py`、`index.js`、`word_planner.py` 等 | `word_progress` 加 2 列(自动迁移) | 无 |
| **P3 造句(mode 4)** | 用目标词说一整句话,LLM 评用法并给出更正 | 改 `word_planner.py`、`word_routes.py`、`word_prompts.py`、`words.js` | 无 | 无 |

## 三、建议顺序与依赖

**建议 P4 → P2 → P3。** 三个阶段基本独立,**唯一的依赖**:P3-S2 要用 P2-S1 新建的 `memory/pt_text.py`(`find_words`)。所以想做 P3,**至少先做完 P2-S1**。
- **P4 先做**:它改进已经上线的填空功能,没生成例句时完全不改变行为;生成后覆盖率从 78.2% 往上走。
- **P2 第二**:便宜,但会改动每一轮聊天的提示词,单独上线观察教练回复有没有变味。
- **P3 最后**:每次造句耗一次 LLM,且出现频率偏低(见下)。

**同一时间只让一个 AI 在做**。三个阶段都会改 `word_routes.py` / `words.js` / `SKILL.md` / `word_planner.py` 中的若干个,**每一步都必须用上一步交付的最新版文件**,不要用最初上传的旧版。

## 四、需要你拍板的点(我的默认选择已写进步骤文件)

1. **P3 造句出现频率会很低**。按设计文档,只给"box ≥ 4 且未掌握的复习词"和"周六加练里的词"出,一天最多 3 道。但 box 3 的词先走填空、过了就毕业,所以 box≥4 且未毕业的词很少;实际主要出现在**周六加练**。我另外加了一条保护:顽固词(`lapses≥3`)和上次答 `again` 的词不出造句(它们要先回到最容易的题)。想更频繁,把 `SENTENCE_BOX_MIN` 改成 3 即可——但那会让造句和填空抢同一批词,并削弱"毕业必过填空"的保证,不建议。
2. **P2 每轮聊天提示词会多约 100~150 token**,教练回复里偶尔会带入目标词(提示词已限定每轮最多 1~2 个、不改 A1/简短/人设)。设计文档估的是 +40 token;我写的提示词更完整,如果你觉得成本高,可以让 AI 把 `_FOCUS_SECTION` 压缩。不喜欢就 `.env` 里 `CHAT_WORD_LINK=0` 重启关闭。
3. **P4 生成的例句没有人工审核**。脚本有自动校验(必须含目标词原形能挖空、有中文、词数合理、去重),但"是不是地道的欧洲葡语"只能靠你抽查(脚本提供 `--dry-run`)。不好的那条在数据库里把 `enabled` 改成 0 即停用。
4. **P2 只检测"当前注入的 ≤5 个目标词"**,你在聊天里用了别的已学词不加分(限成本、防刷)。中文求助模式不加分;教练上一句里已出现的词你复述不加分。
5. **P4 的"今天已用哪条例句"是在读取 `/today` 时记录的**,不是你真正答题时。对一天内的稳定性没影响,只是轮换进度按"每天一轮"推进。

## 五、门槛与验证

每一步做完都**运行它给的测试脚本**,全部通过才算完成。要你自己做的环节:
- **P4-S1 之后**:在能访问词库、`.env` 已配好 LLM 的机器上按 `p4-s1` 末尾的顺序运行 `gen_examples.py`(`--report` → `--dry-run --only-failing --limit 5` → 正式跑 → `--report`)。
- **每个阶段上线后**:按该阶段最后一步里的"上线后观察什么"自己用几天。

## 六、怎么接力(每一步的操作)

1. 新开一个 AI 对话。
2. 先发下面的**接力提示词**,再把该步骤 `.md` 的内容贴进去,并**附上表里列的源文件**(用最新版)。
3. AI 做完后,把产物放到项目对应位置,运行它给的测试脚本。
4. 把 AI 回复末尾的「交接备注」存下来;下一步出问题时一起贴给新的 AI。
5. 在下面的进度表里打勾。

**接力提示词**(每次都用这一段):
```
你是接力实现者，正在给一个葡语学习网页（FastAPI 后端 + 原生 JS 前端）的单词任务功能加新能力。
附件是一个「步骤文件」和需要修改的源文件。
要求：
1. 只做步骤文件里写的事，不要做别的步骤，不要重构，不要改命名。
2. 只阅读步骤文件里列出的文件；定位代码用 grep 锚点，不要信行号。
3. 源文件是 CRLF 换行，改完必须保持 CRLF（新建文件也用 CRLF）。
4. 步骤文件与源文件对不上（锚点找不到、函数签名不同）时，先停下来如实报告，不要自己猜着改。
5. 严格按步骤文件末尾的「交付格式」回复，最后附「交接备注」。
6. 回复要简短，不要复述需求，不要解释显而易见的东西。
7. 测试脚本必须真的运行；运行不了（缺依赖）就说明原因，不要谎称通过。
```

**AI 的两种输出方式**:AI 能直接生成文件 → 输出完整的改后文件;AI 只能聊天 → 只输出**被改动的函数**(完整函数),每段前写清「文件名 + 函数名 + 替换还是插入在哪个函数之后」,新建文件必须完整输出。

## 七、出问题怎么办

| 情况 | 处理 |
|---|---|
| 某一步测试没全过 | 把脚本输出 + 该步骤文件 + 当前源文件发给 AI,让它只修这一步 |
| P2 回退 | `.env` 加 `CHAT_WORD_LINK=0`,重启 |
| P3 回退 | `memory/word_planner.py` 里 `SENTENCE_ENABLED = False`,重启 |
| P4 回退 | 数据库里 `UPDATE word_examples SET enabled = 0;` 即回到只用原例句,不用改代码 |
| AI 额度用完中途停下 | 保存它已写好的内容,换一个 AI:同一个步骤文件 + 已改好的文件 + 一句"上一个 AI 做到了 X,请接着做剩下的" |
| AI 改了步骤文件没提的东西 | 不要采用那部分改动 |
